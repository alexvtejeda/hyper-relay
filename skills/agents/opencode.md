# Adapting the generated agents for OpenCode

OpenCode does not read `.claude/agents/`, so each generated agent the owner wants in OpenCode gets an OpenCode copy
in the same repo: `.opencode/agents/<name>.md`, where the file name is the agent's name (for example
`myapp-planner`). Generate first (SKILL.md, step 2). The body carries over unchanged; the header is translated, and
the planner's guard becomes permission rules.

These rules follow OpenCode's documentation for its V2 agents and permissions. If OpenCode rejects a field or a rule,
tell the owner what it said; do not guess at a fix.

## For each agent

1. **Ask the owner which model.** List the models this OpenCode has configured (from its config, or ask the owner),
   and ask which one this role should use. Do not translate the Claude Code `model:` line: OpenCode reaches other
   providers, and the owner may want one provider's model for the planner and another's for the executor. When
   adapting again, keep the model of the existing `.opencode/agents/<name>.md` unless the owner asks to change it.
   OpenCode writes a model as `provider/model`, optionally `#variant`.
2. **Write `.opencode/agents/<name>.md`:**
   - Front matter: `description` (copied from the generated agent), `mode: subagent`, `model` (the owner's choice),
     `permissions` (below). Nothing else: no `name`, `tools`, `disallowedTools`, `skills` or `hooks`, and none of
     OpenCode's legacy fields (`tools`, `permission`, `prompt`, `maxSteps`, `temperature`, `disable`).
   - Body: first the generated agent's marker line, copied as it is (the `<!-- generated by hyper-relay-agents … -->`
     line), so anyone can see which generation it came from; then the skill paragraph (below), if the agent has a
     `skills:` list; then the generated agent's body, unchanged.
3. **Check `.opencode/agents/` is gitignored** (SKILL.md, step 4): the model is each person's own choice.

## Translation

| Claude Code | OpenCode |
|---|---|
| `.claude/agents/<name>.md` | `.opencode/agents/<name>.md` |
| `model: sonnet` | The model the owner chose, and `mode: subagent` |
| `tools`, `disallowedTools` | `permissions`: an ordered list of `{action, resource, effect}` rules; the last rule that matches wins. The Bash tool is the `shell` action, the Agent tool is `subagent`, Write and Edit are `edit` (the resource is the path) |
| `skills: [hyper-relay:writing-plans]` | No preloading: the skill paragraph below |
| The planner's guard hook | No per-agent hooks: the planner's permission rules below |

## The skill paragraph

Claude Code preloads an agent's skills; OpenCode does not. Right after the marker line, put this paragraph, naming the
skill from the agent's `skills:` list without its `hyper-relay:` prefix (`writing-plans` for the planner,
`executing-plans` for the executor):

```markdown
**First, before anything else:** load the `writing-plans` skill with the `skill` tool. Where this file says
`hyper-relay:<name>`, use the skill `<name>`.
```

## Permissions

In a rule, `*` matches any characters, `/` and spaces included, and a `shell` rule ending in ` *` also matches the
command with no arguments. OpenCode splits a compound command (`a && b`) and checks every part.

**Executor** (`disallowedTools: Agent`):

```yaml
permissions:
  - action: subagent
    resource: "*"
    effect: deny
```

**Reviewer** (`disallowedTools: Agent, Edit, Write, NotebookEdit, Workflow`):

```yaml
permissions:
  - action: subagent
    resource: "*"
    effect: deny
  - action: edit
    resource: "*"
    effect: deny
```

**Planner** (its guard: read-only git, `git add`/`git commit` of plans, `quartz link-doc`, and writing plans only):

```yaml
permissions:
  - action: subagent
    resource: "*"
    effect: deny
  - action: edit
    resource: "*"
    effect: deny
  - action: edit
    resource: "*docs/superpowers/plans/*.md"
    effect: allow
  - action: shell
    resource: "*"
    effect: deny
  - action: shell
    resource: "git status *"
    effect: allow
  - action: shell
    resource: "git log *"
    effect: allow
  - action: shell
    resource: "git show *"
    effect: allow
  - action: shell
    resource: "git diff *"
    effect: allow
  - action: shell
    resource: "git rev-parse *"
    effect: allow
  - action: shell
    resource: "git ls-files *"
    effect: allow
  - action: shell
    resource: "git ls-tree *"
    effect: allow
  - action: shell
    resource: "git grep *"
    effect: allow
  - action: shell
    resource: "git blame *"
    effect: allow
  - action: shell
    resource: "git merge-base *"
    effect: allow
  - action: shell
    resource: "git cat-file *"
    effect: allow
  - action: shell
    resource: "git for-each-ref *"
    effect: allow
  - action: shell
    resource: "git describe *"
    effect: allow
  - action: shell
    resource: "git shortlog *"
    effect: allow
  - action: shell
    resource: "git branch"
    effect: allow
  - action: shell
    resource: "git branch --show-current"
    effect: allow
  - action: shell
    resource: "git branch --list *"
    effect: allow
  - action: shell
    resource: "git worktree list *"
    effect: allow
  - action: shell
    resource: "git add docs/superpowers/plans/*.md"
    effect: allow
  - action: shell
    resource: "git commit -m * -- docs/superpowers/plans/*.md"
    effect: allow
  - action: shell
    resource: "quartz link-doc docs/superpowers/plans/*.md"
    effect: allow
  - action: shell
    resource: "*--output*"
    effect: deny
  - action: shell
    resource: "*--ext-diff*"
    effect: deny
  - action: shell
    resource: "git commit * -a *"
    effect: deny
  - action: shell
    resource: "git commit *--all*"
    effect: deny
  - action: shell
    resource: "git commit *--amend*"
    effect: deny
  - action: shell
    resource: "git commit *--no-verify*"
    effect: deny
```

There is no `git -C` rule: the OpenCode planner runs in the main checkout, and `git show <branch>:<path>` reads other
branches. Tell the owner that the agent's body still says to use `git -C`, and that OpenCode will refuse it.

**Say this plainly to the owner when adapting the planner:** these rules only come close to the guard. The guard
reads a command's structure, and patterns cannot:
- `*` matches spaces too, so `git add docs/superpowers/plans/a.md src/b.md` matches the `git add` rule, and the
  `git commit` rule cannot insist that every path after `--` is a plan.
- `git log *` and the other read-only rules accept any flags; the two deny rules catch only `--output` and
  `--ext-diff`, the flags that write a file or run a program.
- The guard refuses `$(…)` and backticks outright; whether OpenCode's shell scanner checks a command inside them is
  not documented.
